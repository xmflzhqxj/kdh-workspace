# 🚀 Vercel & GitHub Action Deployment Rules

이 문서의 지침은 현재 프로젝트(`kdh-hokkaido`)가 Vercel 프로덕션 환경(Production Environment) 및 GitHub `main` 브랜치 자동 연동 시스템에서 단 1의 빌드 오류도 없이 완벽하게 작동하도록 코드를 제어하기 위한 절대 규칙(Absolute Rules)이다. 

Codex AI는 코드를 수정, 리팩토링, 또는 추가할 때 아래 명세 및 규칙을 반드시 준수하여 코드를 작성해야 한다.

---

### 🎨 1. 프로젝트 핵심 프레임워크 및 환경 설정
- **기반 프레임워크:** React (TypeScript) + Vite 기반 웹 어플리케이션
- **배포 타겟 주소:** `https://kdh-hokkaido.vercel.app`
- **트리거 브랜치:** `origin/main` (해당 브랜치에 코드가 push/merge 될 때 Vercel 자동 배포 구동)

### 🛠️ 2. 코드 작성 및 리팩토링 절대 준수 규칙 (Vite Standard)
Vercel 서버에서 `vite build` 명령어 실행 시 컴파일 에러가 발생하면 전체 배포가 중단되므로 아래 사항을 항상 검증하며 코드를 생산한다.

1. **출력 디렉토리 경로 준수:** 빌드 결과물은 항상 프로젝트 루트의 `dist` 폴더에 생성되는 구조를 유지한다.
2. **TypeScript 타입 체킹 엄수 (`noImplicitAny` 대응):** 어떠한 컴포넌트나 비즈니스 로직에서도 생략된 `any` 타입 또는 타입 불일치 에러를 남기지 않는다. 데이터 구조 추가 시 명확한 `interface` 또는 `type`을 먼저 선언한다.
3. **라이브러리 참조 누락 방지:** 반드시 `package.json`에 명시될 수 있는 표준 모듈만 사용하며 로컬 바이너리에 의존하는 특수 환경 패키지는 지양한다.

### 🗺️ 3. 주요 컴포넌트 데이터 인터페이스 유지 보수 규칙
- **구글맵 파싱 엔진 (`map_location` 변환):** 단순 주소 텍스트 또는 구글맵 단축 URL이 들어와도 iframe 주소(`&output=embed`)로 안전하게 가공해 주는 파서(Parser) 로직의 안정성을 보존한다.
- **항공권 티켓 컴포넌트 (Boarding Pass UI):** 예약 1(가는 편)과 예약 2(오는 편)로 나누어진 티켓 고유 데이터 구조와 바코드/절취선 스타일링을 훼손하지 않는다.
- **이원화 체크리스트 (준비물/기념품 및 소유자 시스템):** 소유자(`동현`, `민희`, `공통`)에 따른 이원화 필터 및 태그 색상 매핑 구조를 엄수한다.

### 📊 4. Supabase 실시간 연동 인터페이스 명세
- `travel_places`, `checklist` 테이블과 실시간 동기화(`Realtime`)되는 데이터 구독 및 트랜잭션 흐름을 유지한다.
- 환경 변수가 연결되지 않은 로컬 상태에서도 웹앱이 크래시(Crash) 없이 모크 데이터(Mock/Seed Data)로 부드럽게 구동되는 2중 안전장치(Fallback State)를 상시 유지하라.
